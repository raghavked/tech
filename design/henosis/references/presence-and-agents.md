# Presence and agents for Henosis

Henosis is one session where a team's people and agents work together. Two crafts matter: multiplayer presence (who is here, where, doing what) and how agent products make their agent watchable. A colleague is someone you can *see working*, *point at*, *interrupt politely* and *read in the same grammar as everyone else*.

## What the best work does

**Presence is ephemeral, embodied and colour-keyed.** Figma's cursor chat: press `/`, a bubble anchors to your cursor, others see it as you type, no send step, 52 characters, gone five seconds after you stop, never logged (https://help.figma.com/hc/en-us/articles/4403130802199-Use-cursor-chat-in-Figma-Design). It exists to bring back "a quick chair swivel to catch up with a co-worker" (https://www.figma.com/blog/talk-it-out-in-figma-and-figjam/); the multiplayer bet was that seeing others "without interrupting the person doing the work" beats the feared "hovering art director" (https://www.figma.com/blog/how-figmas-multiplayer-technology-works/). Liveblocks makes these primitives: container-relative cursors on springs, avatar stacks with `+N` overflow, selections as a 2px outline in the holder's colour, typing flags that clear on timeout (https://liveblocks.io/docs/use-cases/presence). Google Docs adds the gesture everyone copies: click an avatar to jump to that cursor.

**Agents can enter the same presence system with no new UI.** Liveblocks lets a server set presence for an agent with a name, avatar, colour and TTL, so it "appears in `useOthers` alongside real users, so existing avatar stack components work without any changes", carries `focusedField` or `typing` like a person, and expires on its own if the workflow crashes (https://liveblocks.io/docs/guides/enabling-agentic-workflows-with-liveblocks). This is the strongest argument for unity: do not build an agent panel, put the agent in the room.

**Pairing tools make control legible, not exclusive.** Tuple rings the avatar of whoever holds mouse and keyboard, auto-assigns a paint colour per participant, fades drawings after a few seconds, and made a call "a host and multiple equally-capable guests" (https://docs.tuple.app/pairing-with-tuple/interacting-with-a-shared-screen, https://tuple.app/blog/three-player-improvements/). Multi's founding line is "I would have pointed with my finger": cursors shared by default, no "host/participant, presenter/viewer, or even driver/navigator" (https://multi.app/changelog/cursor-sharing, https://multi.app/blog/launching-multi-multiplayer-collaboration-for-macos). Arc's shared Spaces are the light form: one link opens the same collection even without the app (https://techcrunch.com/2023/10/27/startup-browser-maker-arc-now-lets-you-share-spaces-folders-and-split-views-with-non-arc-users/).

**Agents feel like colleagues when they have a desk you can look over.** Devin's workspace is Shell, Browser, Editor, Planner, "very much what you have when you talk to a developer"; a Following switch moves your view as Devin moves, a logo beside the active tab says where Devin *is*, a status line names the current task, and the composer says "(won't interrupt Devin)" (https://ppaolo.substack.com/p/in-depth-product-analysis-devin-cognition-labs). Later releases shrink the idea: a favicon dot, green working, orange waiting for you; sidebar groups Working / Ready / Blocked (https://releases.sh/cognition/release-notes). Cursor applies edits live in the diff and lets you queue or "steer the active turn at the agent's next tool call" (https://cursor.com/docs/agent/overview). Replit puts agent work on a Drafts / Active / Ready / Done board, each task a thread with a live status dot (https://docs.replit.com/core-concepts/agent/task-system). Claude Code gives a wait a face: a six-glyph asterisk cycle, `∴` for reasoning, a shimmering verb, text that eases toward red as tokens stall, and a byline like "Cooked for 1m 6s" (https://blog.alexbeals.com/posts/claude-codes-thinking-animation, https://dev.to/vmxd/what-the-claude-code-source-taught-me-about-engineering-taste-12bd). Perplexity's Model Council frames several agents as a board: one synthesis showing "where the models agree and where they differ", contributors named beneath (https://www.perplexity.ai/help-center/en/articles/13641704-what-is-model-council).

The pattern: *same room, same primitives, same courtesy*. One presence system; one stream for everyone's actions; interruption as handoff, not kill; status readable from across the office.

## Ten elements for Henosis

Person = chocolate arc, agent = apricot arc, both on cream, as the mark already states. Hue is the only difference between the two kinds of participant.

1. **The Arc Pointer.** Cursors are the brand arc, not an arrow: `<use href="#mark-bare">` clipped to one arc with `stroke-dasharray="0.5 0.5" pathLength="1"`, chocolate for a person, apricot for an agent; when two pointers rest on the same element the second arc draws in and the ring closes. Screen: Session, Details. Unity: the logo is literally two participants meeting.

2. **The Step Bubble.** Agents get cursor chat, not a status panel: the current step ("reading invoice.ts") rides the agent's pointer as a `max-width: 52ch` bubble, `animation: fade 300ms 5s forwards` after each step, never logged. Screen: Session, Details. Unity: a person types "is this the latest?" in the identical bubble.

3. **The Hold Outline.** Whatever someone is working on takes `outline: 2px solid var(--holder); outline-offset: 2px` plus a `::after` name tab, `--holder` set from presence. Screen: Plan card, Details, Memory. Unity: a field held by Mira and a field held by Cy's agent look the same except for the arc colour.

4. **One Stack.** A single avatar stack, `margin-inline-start: -8px; border: 2px solid var(--canvas)`, agents shown as the mark, no robot icon, with `animation: expire var(--ttl) linear forwards` on opacity so an agent whose heartbeat lapses dims before it leaves. Screen: Session header, Team panel. Unity: nobody is in a separate list.

5. **One Column.** Human messages and agent tool-call cards share one stream and one card, differing only in `border-inline-start: 3px solid var(--who)`; long tool output is a `<details>` that auto-collapses once the next message lands. Screen: Session. Unity: the worklog is the conversation.

6. **The Follow Band.** Click any avatar to follow; a `position: sticky; top: 0` band reads "Following Cy's agent · Esc to stop" and the pane takes `box-shadow: inset 0 0 0 2px var(--apricot-deep)` so you know the view is borrowed. Screen: Session, Details, Desktop panes. Unity: following a colleague and following an agent are one gesture.

7. **The Steer Line.** The composer placeholder says who hears it and when: "Say something · reaches Cy's agent at its next step"; queued messages sit in a drawer above the input, `translate: 0 var(--travel)` on `--sheet`, with Send now. Screen: Session composer, Mobile. Unity: you never "stop" a colleague, you tell them.

8. **Fade Paint.** Anyone, person or agent, can draw on the preview: `<path pathLength="1">` draws in with `stroke-dashoffset` 1→0, holds, then fades over four seconds; an agent pointing at "this button" uses the same stroke in apricot. Screen: Details preview, Release gate. Unity: pointing with a finger is the same act for both.

9. **The Agreement Ring.** When several participants weigh in on a decision, each line of the summary carries a small mark: closed ring (`stroke-dasharray="1 0"`) where they agree, open ring (`"0.42 0.08"`) where they differ, contributors named beneath. Screen: Approvals, Plan card. Unity: consensus is the brand's closed shape.

10. **The Same Byline.** Every finished turn ends in one grammar, `font-variant-numeric: tabular-nums; color: var(--ink-muted)`: "Mira · 3 edits · 2m 10s" and "Cy's agent · 11 tool uses · 1m 06s"; while a turn runs the text eases toward the warning ink as updates stall. Screen: Session, Inbox, Manager overview. Unity: effort is measured the same way for everyone.
