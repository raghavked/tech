Guides/Approvals/Release gates

Release gates

An irreversible action waits for the people who will live with it. A gate is an approval with a ratings rule: enough contributors, rating high enough, before the agent may push.

AWritten by Ana, Payments·Updated today·7 min read

What a gate is #

Every tool call carries a risk class: read, write, exec, external or irreversible. The session's policy says who may approve each class. For irreversible calls (a push to main, a migration, a refund) the default is not one person's click but a release gate: a rule that counts ratings.

When Dee's agent on Invoice PDF: tax lines and proration is ready to push, it asks. Ana and Cy, who consume the Billing page and Checkout, each rate the approval. The kernel grants the gate only when the rule is met. Bo can click Approve without a rating; that is a voice, not a vote.

The default rule. Two contributors rating 4 or more on average. Approve without picking a star sends a 4. Observers see the gate but cannot vote.

A gate in the stream #

This is the notice the Payments team sees in the session, in the approvals queue, in the inbox and in Slack. The same component, the same rule, everywhere.

Writing the rule #

Gates live in the session policy under approvals. A rule is { ratings: { min, average, of } }: how many people, how high on average, at which role. Set it when the session is created, or change it later as an owner.

json{
  "approvals": {
    "exec":         { "role": "contributor" },
    "external":     { "role": "driver" },
    "irreversible": { "ratings": { "min": 2, "average": 4, "of": "contributor" } }
  },
  "planFirst": true,
  "tokenBudget": 400000   // soft: a number people watch, not a gate
}

The verdict is derived in the fold, so every replica, the CLI, the web client and Slack, reaches the same answer from the same events. A replay of the session reaches it too, with no model calls.

Risk classes and their defaults

ClassExamplesDefault approval
readRead a file, list the branch, fetch the invoice PDF fixtureNone
writeEdit billing/tax-lines.ts, write a testNone while the plan is approved
execRun the Checkout test suite, build the PDFOne contributor
externalCall the tax rate service, post to #billingThe driver
irreversiblePush to main, run the proration migration, issue a refundRelease gate: 2 contributors at 4+

Who counts #

  • Contributors and above rate. One rating per person; a second pick replaces the first.
  • The driver can ask the agent to revise instead, which withdraws the request and brings a new one.
  • Owners may grant outright. The notice records that it was granted by decision, not by the rule.
  • Agents never vote on their own gates, even when they are members of the group.
Why ratings and not a count. A count says two people clicked. An average says how they felt. "Two at 4+" lets Ana say "fine" and Cy say "good" and still hold the line when one of them says "not yet".

Where a gate shows up #

The notice in the stream, the approvals queue, the inbox row, the command palette ("Rate the gate on invoice-pdf"), and the Slack thread for the session, where the buttons carry the stars. Rate from any of them; the rest update.
