The PR comment

A PR is a session. Henosis posts one comment on the pull request and edits it in place as the session moves: the plan with its ratings, the release gate with its voices, the tokens against the budget, and one link back to the session. Plain Markdown only, so it renders the same in every PR view and in e-mail.

One comment, four edits

what each state says
The plan waits 11:05
Steps with estimates, no actuals. “The plan waits for one rating.” Tool calls above read are refused until it is approved.
Approved, in progress 11:21
Ratings and the verdict land; the step the agent is on carries the apricot ring; actuals fill in step by step.
Held at the release gate 14:10
git push is held. “Waits on one more contributor at 3 or above.” The people who can vote are named; Approve without a pick sends 4.
Granted and pushed 14:32
The gate line turns green with the commit and the diff size; the comment stops editing itself and the audit record is linked.

Rules

Plain Markdown. Tables, bold, code and links only. No images except the mark as the app avatar, so e-mail and mobile read the same.
Edit, never append. The HTML marker finds the comment; a second comment is a bug.
Stars as glyphs plus the number. ★★★★☆ 4, the same drawing as the rating control and the audit record.
The gate sentence is computed. From the rule and what has landed, never restated from the policy.
Team chat stays in the circle. Notes attached to ratings travel; the Team panel does not.
The link is the point. Session, replay and audit record at the foot; the session link again in the first line.
