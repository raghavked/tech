The inbox: what needs you, across projects

Agents run for hours; people come and go. The inbox is the one place a person sees every question waiting on them from every session they are on, answers it without leaving, and watches it turn into a line. It is drawn as rows under a project name, not cards: an icon for the kind, the ask as a sentence, the state in words with a dot, and the answer on the right. Dee, the lead on Northwind, is reading.

Desktop

The inbox is a sidebar destination beside Projects, with a count that only counts what needs this person. Groups follow the project tree; sessions appear in the by-line, not as a level. The accent sits on the first undecided answer, the next decision; the rest wait in outline until they reach the top.

One row

Every kind of item uses the same four parts, so the eye learns one shape. Nothing on the row is coloured except the dot and, on one row per screen, the primary button.

1The ask as a sentence. The exact call, since what is approved is the hash of that call; a question mark for approvals, a choice for contentions, a plain sentence for handoffs and blocks.
2The by-line. Whose agent, which session as a link, the state as a status word with a dot, the words that matter ("cannot be undone"), and how long it has waited.
3The answer. Buttons that name the act. Rows that are not this person's to answer say so in grey instead of hiding the buttons.
The icon is the kind: a question, a fork, an arrow, a pause. It is the only element that changes between kinds.

The tray popover

On desktop the Tauri shell keeps a mark in the menu bar; it fills in when something needs you. The popover is the same rows, narrower: the answer drops under the by-line, the project moves into it, and the done group is cut to the last two. One click answers; "Open Fold" is the only way out.

Menu bar mark outlined: nothing needs you. The last three settled items stay as lines so the answer you just gave is still visible.

Counts. The sidebar number, the title, and the menu bar mark all count the same thing: items this person can answer. Items waiting on others never make a number; they are listed, in grey, with the words "not yours to answer".

Order. Within a project, rows are ordered by what the kernel would block on first: irreversible approvals, then contentions on goal, then blocks on a lead direction, then the rest, each oldest first. The accent follows that order to the top row.

Web and mobile. The web app shows the same page; the popover does not exist there and the sidebar count is the signal. On the phone the inbox is the first tab and each row stacks the answer under the by-line exactly as the popover does.
