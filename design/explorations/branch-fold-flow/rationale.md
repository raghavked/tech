# Branch and fold: rationale

**Decision.** A branch is a pointer to a turn, so forking is drawn as an action on a turn: a thin rail under any agent message, one notice with a name and a line of why, then a settled line at that turn and an indented row under the session in the sidebar. Compare is the one place the column splits, and it splits into two copies of the same column from a shared checkpoint divider, each with a name, a status word and three facts; the composer gives way to Close and Fold. The fold is a quiet notice in main's stream with one row per file. The single conflict is the row that opens: both sides as three mono lines, a radio each, and a link to let the agent rewrite. Under the rows, what the fold carries in: Dee's constraint by union, Cy's steer meeting Ana's as a contention. Settled, the notice is a line, the merge a divider, the branch row reads "folded", and the carried contention arrives as an ordinary notice.

**Rejected.** A branch graph (branches are rows). A diff viewer for the conflict (three lines per side decide most; the rest go to the agent). A merge modal. Colouring the branch.

**Carry forward.** The hover rail under turns; the checkpoint divider; file rows with merged / added / both changed as the one merge component; carried-directive rows; "folding" and "folded" as sidebar row words beside "needs you".
