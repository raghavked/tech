# Observability for Fold sessions: OpenTelemetry GenAI, span mapping, export, cost

*Research memo, 2 October 2026. Topic slug: observability-otel-genai.*

## Why it matters for Fold

Fold's log is already the best trace of an agent session anyone has: every model call, tool call, directive, approval, contention and handoff is a hash-chained event with a replayable fold. What it lacks is the two things platform teams actually ask for before they let an agent run for a week on a project: (1) a way to see Fold sessions next to the rest of the system in the tooling they already pay for (Datadog, Honeycomb, Grafana), and (2) a cost number per project, per engineer and per session they can put on a dashboard and a budget. Today `agent.model.completed` records `model`, `text` and `toolCalls` but not token usage (`packages/protocol/src/index.ts`), and `packages/runner/src/claude.ts` discards `response.usage`. Nothing is exported anywhere.

Two properties of Fold change how observability should be built. First, because state is a pure fold of the log, telemetry can be *derived* from the log by a reducer-style tap rather than emitted from inside the runner. That makes export idempotent across runner crashes and resumes, lets a replay backfill a backend, and keeps the web, desktop and CLI clients out of the business of emitting anything. Second, Fold knows things no single-user agent product can export: which human's directive the agent was acting on, who approved the tool call, how long a turn sat waiting on a quorum, and which contention blocked a scope. Those are the attributes a team lead wants on a dashboard, and no vendor convention has a slot for them yet.

## Prior art

1. **OpenTelemetry GenAI semantic conventions** (spans, agent spans, metrics). Now maintained in their own repository, `open-telemetry/semantic-conventions-genai`; the pages under `opentelemetry.io/docs/specs/semconv/gen-ai/` and the old `semantic-conventions` tree are redirect stubs (verified 2026-10-02 via raw GitHub; the live spec site is egress-blocked here, so attribute details below are from memory and marked UNVERIFIED). Status is still "Development". Operations: `chat`, `create_agent`, `invoke_agent`, `execute_tool`; span name `"{operation} {model|agent|tool}"`; attributes `gen_ai.operation.name`, `gen_ai.provider.name` (renamed from `gen_ai.system` in semconv 1.37), `gen_ai.request.model`, `gen_ai.response.model`, `gen_ai.conversation.id`, `gen_ai.agent.id/name`, `gen_ai.tool.name`, `gen_ai.tool.call.id`, `gen_ai.usage.input_tokens/output_tokens`, `gen_ai.response.finish_reasons`; message content under `gen_ai.input.messages` / `gen_ai.output.messages` is opt-in. Metrics: `gen_ai.client.token.usage` (histogram, `{token}`, split by `gen_ai.token.type` = input|output) and `gen_ai.client.operation.duration` (s). No cost metric is defined. https://github.com/open-telemetry/semantic-conventions-genai (accessed 2026-10-02).
2. **Claude Code monitoring (OTel export).** The closest shipped analogue to what Fold needs: metrics `claude_code.cost.usage` (USD, explicitly "estimated, client-side from published pricing"), `claude_code.token.usage`, `session.count`, `active_time.total`, `code_edit_tool.decision`; events `api_request` (with `cost_usd`, `duration_ms`, tokens), `tool_result`, `tool_decision` (accept/reject with `source`), `api_refusal`; attributes `session.id`, `user.email`, `organization.id`; cardinality switches (`OTEL_METRICS_INCLUDE_SESSION_ID` etc.); content redaction gates (`OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_TOOL_CONTENT`); managed settings that lock the OTLP destination; a beta trace tree `interaction > llm_request | hook | tool > tool.blocked_on_user | tool.execution`. https://code.claude.com/docs/en/monitoring-usage (accessed 2026-10-02).
3. **Datadog LLM Observability, OTLP ingestion.** Accepts OTLP traces with headers `dd-api-key` and `dd-otlp-source=llmobs`; recognises OTel GenAI 1.37+ (`gen_ai.*`), OpenInference (`openinference.span.kind`) and OpenLLMetry attributes; derives span kind from `gen_ai.operation.name` (`chat` -> LLM, `execute_tool` -> tool, `invoke_agent`/`create_agent` -> agent, unmapped -> workflow); reads tokens from `gen_ai.usage.*` and cost from `gen_ai.cost.*` attributes (a Datadog extension, not in semconv); span links are stored but not rendered in execution graphs; data may also land in APM traces, so access controls must be mirrored. https://docs.datadoghq.com/llm_observability/instrumentation/otel_instrumentation/ (accessed 2026-10-02).
4. **OpenLLMetry (Traceloop).** Apache-2.0 OTel instrumentation for 15+ providers including Anthropic, with a separate `openllmetry-js`; claims its conventions were upstreamed into OTel GenAI; exports to Datadog, Honeycomb, Grafana, New Relic, the Collector. https://github.com/traceloop/openllmetry (accessed 2026-10-02).
5. **OpenInference (Arize).** Span kinds LLM, CHAIN, TOOL, AGENT, RETRIEVER; attributes `openinference.span.kind`, `llm.model_name`, `llm.token_count.*`, `tool.name`, `session.id`, `user.id`; npm packages including `@arizeai/openinference-instrumentation-anthropic` and an instrumentation for the Claude Agent SDK. https://github.com/Arize-ai/openinference (accessed 2026-10-02).
6. **Honeycomb.** UNVERIFIED (docs.honeycomb.io blocked). Honeycomb ingests plain OTLP with an `x-honeycomb-team` header and favours wide, high-cardinality spans with derived columns, which suits a `cost_usd` derived from token attributes. https://docs.honeycomb.io/ (not accessed).

## What to borrow

- **Speak `gen_ai.*` natively, not a vendor dialect.** Datadog maps `gen_ai.operation.name` straight to its span kinds, and OpenLLMetry/OpenInference are converging on the same names. One exporter, three backends.
- **Turn = `invoke_agent` span; model call = `chat` child; tool = `execute_tool` child.** This is both the OTel agent-span shape and Claude Code's beta tree. Fold's `agent.turn.started/ended`, `agent.model.completed` and `agent.tool.requested/completed` already delimit these.
- **A "blocked on human" child span.** Claude Code's `tool.blocked_on_user` is exactly Fold's `approval.requested` to final `approval.voted`. Fold can add who voted and quorum size.
- **Estimated cost as a first-class metric with an honesty label**, as Claude Code does: computed client-side from a pricing table, labelled estimated, and reconciled against the provider's billing export.
- **Redaction gates and cardinality switches** as configuration, defaulting closed. Fold's log already holds every prompt; the exporter must not leak it by default.
- **Session id as `gen_ai.conversation.id`**, with user and org resource attributes, so backends group by session without custom work.

## What is unsolved

- **The conventions are not stable.** `gen_ai.system` became `gen_ai.provider.name`; the repo moved; agent spans and content attributes are still "Development". Anything Fold ships needs a version pin and an attribute-mapping layer, not hard-coded strings scattered through the runner.
- **No cost in the spec.** Datadog reads `gen_ai.cost.*`, Claude Code emits `cost_usd`; neither is standard. Anthropic's cache read/creation tokens have no `gen_ai.token.type` value either.
- **Week-long sessions do not fit one trace.** Backends cap trace size and age; Datadog does not render cross-trace links. The honest unit is one trace per turn, linked by `gen_ai.conversation.id`, with the session view living in Fold itself.
- **No vocabulary for many principals.** `user.id` is singular. Who steered, who approved, who was driver, which rank won arbitration, which scope is contended: none of it exists in any convention. Fold must define a `fold.*` namespace and accept it is proprietary.
- **Forks and merges.** Branching histories have no span model. A branch attribute plus span links to the fork checkpoint is the best available approximation.
- **Deterministic ids versus backend expectations.** Deriving span ids from event hashes makes export idempotent on resume and replay, but a replayed export re-sends identical spans, and backends dedupe inconsistently.

## Concrete recommendations for Fold

1. **Record usage in the event, not just in the exporter.** Extend `agent.model.completed` in `packages/protocol/src/index.ts` with `usage: { inputTokens, outputTokens, cacheReadTokens, cacheCreationTokens }`, `latencyMs`, `stopReason` and `requestId`; make `ModelResponse` in `packages/runner/src/model.ts` carry the same, and have `packages/runner/src/claude.ts` fill it from `response.usage`. Replay then reproduces cost exactly, with no provider call.
2. **New package `packages/telemetry`: a log tap, not runner instrumentation.** `fold(events)` style reducer `exportSpans(events, opts)` that emits OTLP via `@opentelemetry/sdk-trace-base` and `@opentelemetry/exporter-trace-otlp-http`. Mapping in `packages/telemetry/src/mapping.ts`: one trace per turn, root `invoke_agent fold` (`gen_ai.agent.name="fold"`, `gen_ai.conversation.id=sessionId`, `fold.branch`, `fold.epoch`, `fold.turn`, link to the previous turn's root), child `chat {model}` from `agent.model.completed` (`gen_ai.operation.name=chat`, `gen_ai.provider.name=anthropic`, `gen_ai.usage.*`, `gen_ai.response.finish_reasons`), child `execute_tool {name}` from `agent.tool.requested` to `agent.tool.completed` (`gen_ai.tool.name`, `gen_ai.tool.call.id`, `fold.tool.risk`, `error.type` when `!ok`), and grandchild `approval {id}` from `approval.requested` to the deciding `approval.voted` (`fold.approval.rule`, `fold.approval.voters`, `fold.approval.outcome`). Span and trace ids derive from event hashes (`packages/kernel/src/hash.ts`) so a resumed runner or a replay produces the same spans. Directives, contentions, handoffs and fleet claim denials become span events on the current turn span with `fold.directive.mode/scope/rank/outcome` (applied, shadowed, contention).
3. **Metrics and cost in `packages/telemetry/src/metrics.ts` and `pricing.ts`.** Emit `gen_ai.client.token.usage` and `gen_ai.client.operation.duration` per the spec, plus `fold.cost.usage` (USD, counter, estimated) computed from a versioned pricing table keyed by model id, with `cache_read` and `cache_creation` priced separately. Attributes: `fold.project.id`, `fold.session.id`, `fold.engineer.id` (the session owner) and `fold.driver.id` (the driver at the turn), with Claude-Code-style include switches for the high-cardinality ones. Also emit `fold.turn.blocked_on_humans` (s, histogram) and `fold.contention.open` (gauge), the two numbers a lead cannot get anywhere else.
4. **Fleet cost roll-up in `packages/fleet`.** Add a `cost` section to the project ledger fold (`packages/fleet/src/ledger.ts`) and the fleet brief (`packages/fleet/src/brief.ts`): tokens and estimated USD per session, per engineer and total, computed from the same `usage` payloads, so `fold fleet ledger.json` prints it offline and the project page in `design/web-project.html` can show one quiet line per session ("$4.12 today, 1.3M tokens") in the existing muted text style. No chart in phase 0.
5. **Configuration and privacy in `packages/server/src/server.ts`.** `FOLD_OTEL_EXPORTER=otlp|console|none`, standard `OTEL_EXPORTER_OTLP_*` variables, and gates `FOLD_OTEL_CONTENT=none|tools|messages` defaulting to `none`, so `gen_ai.input.messages`/`output.messages` are never exported unless an owner turns it on. Document the Datadog recipe (`dd-otlp-source=llmobs`) and Honeycomb (`x-honeycomb-team`) in `docs/04_technical_architecture.md`, and note in `docs/07_security_and_compliance.md` that exported spans leave the hash chain and inherit the backend's retention and access model.
6. **`fold export <log.json> --otlp <endpoint>` in `packages/cli/src/main.ts`.** Backfill from a log, which also doubles as the test: `packages/telemetry/test/mapping.test.ts` asserts the span tree for `store-demo/sessions/demo/log.json` is identical whether produced live or by replay.
