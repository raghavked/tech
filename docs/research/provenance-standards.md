# Provenance standards for attributed team memory and commits

Research memo, 2026-10-02. Topic: W3C PROV-O, in-toto/SLSA attestations, git trailers and Claude-Session links, signed commits. Goal: map Fold's log and memory entries onto PROV and propose an export. Several primary sources (w3.org, slsa.dev, datatracker.ietf.org) were blocked by the egress proxy; claims drawn only from search snippets are marked UNVERIFIED.

## Why it matters for Fold

Fold already has the raw material of provenance: every session is a hash-chained log (`SessionEvent.id` = sha256 over prev, branch, seq, actor, ts, body in `packages/protocol/src/index.ts`), approvals are bound to the content hash of the exact call, merges record base checkpoint and resulting tree, and every memory entry carries an `Attribution` of engineer, agent, session and commit (`packages/memory/src/events.ts`). What Fold lacks is a way to say any of this to the outside world. A commit lands in GitHub with no verifiable link back to the session that produced it, the directive that steered it, or the two humans who approved the irreversible call. A memory entry says "added by Ana, session billing-42, commit 9f3c1a" inside Fold, but an auditor, a compliance tool or another vendor's agent cannot consume that. Provenance standards give Fold three things: a vocabulary (PROV) so the attribution graph is portable; an envelope (in-toto Statement + DSSE) so the graph is signed and bound to artifact digests; and a transport (git trailers, signed commits, attestation refs) so the link travels with the code. For a product whose pitch is "who said so, and on whose authority", exportable provenance is the proof.

## Prior art

1. **W3C PROV-O** (Recommendation, 2013). https://www.w3.org/TR/prov-o/ (blocked; mirror https://www.w3.org/ns/prov-o-20130430, accessed 2026-10-02). Three starting classes, Entity, Activity, Agent, with Person, Organization and SoftwareAgent as agent subclasses; binary relations wasGeneratedBy, used, wasAttributedTo, wasAssociatedWith, actedOnBehalfOf, wasDerivedFrom (with Revision, Quotation, PrimarySource), wasInvalidatedBy; and a "qualified" pattern (qualifiedAssociation with hadRole and hadPlan, qualifiedAttribution) for attaching metadata to a relation. Bundles are named sets of provenance statements that can themselves have provenance.
2. **PROV-JSON and PROV-JSONLD** (W3C Member Submissions, 2013 and 2024). https://www.w3.org/Submission/prov-json/ and https://www.w3.org/submissions/2024/SUBM-prov-jsonld-20240704 (accessed 2026-10-02, snippets only). PROV-JSON is a compact keyed-by-type JSON encoding; PROV-JSONLD adds a JSON-LD context so the same document is linked data. Either is a reasonable export target; PROV-JSONLD is the newer and more tool-friendly.
3. **in-toto Attestation Framework, Statement v1**. https://github.com/in-toto/attestation/blob/main/spec/v1/statement.md (accessed 2026-10-02, verified via raw). `{"_type":"https://in-toto.io/Statement/v1","subject":[{"name","digest":{alg:hex}}],"predicateType":URI,"predicate":{}}`. Subjects are matched purely by digest; the statement is wrapped in a DSSE envelope and signed. CNCF-graduated, and the format under SLSA provenance and GitHub Artifact Attestations.
4. **SLSA Provenance v1 predicate**. https://slsa.dev/provenance/v1 (blocked; UNVERIFIED from snippets, accessed 2026-10-02). `buildDefinition` (buildType, externalParameters, internalParameters, resolvedDependencies) and `runDetails` (builder.id, metadata with invocationId/startedOn/finishedOn, byproducts). Useful as a shape: a session is a "build" whose external parameters are the directives and whose resolved dependencies are the memory entries read.
5. **Occasio AI-Agent Behavioral Attestation v1** (Draft 1). https://github.com/occasiolabs/occasio/blob/HEAD/spec/agent-attestation/v1/README.md (accessed 2026-10-02, verified via raw). An in-toto predicate for "what an AI coding agent did during a single bounded session": subject `occasio:run:<uuid>` whose digest is the final hash of a hash-linked audit chain; fields for tool-call counts, blocked attempts, active policy hash, model id, session id, timestamps, files changed; signed with DSSE via Sigstore keyless OIDC; verification = signature + byte-equal predicate + re-walking the chain. This is the closest analogue to Fold's log head.
6. **Sigstore gitsign**. https://github.com/sigstore/gitsign (accessed 2026-10-02). Keyless commit signing: OIDC identity → 10-minute Fulcio x509 certificate → signature recorded in Rekor; `gpg.format x509`, `gpg.x509.program gitsign`. Limitation: GitHub does not show these as "Verified" because Sigstore's root is not in its trust store.
7. **Git trailers and AI attribution practice**. git-interpret-trailers (https://git-scm.com/docs/git-interpret-trailers, UNVERIFIED, mirror snippets accessed 2026-10-02): RFC-822-style `Token: value` lines at the end of the message, with `trailer.<token>.ifExists` policies and `git commit --trailer`. Claude Code appends `Co-Authored-By: Claude ...` and, for cloud or Remote Control sessions, a `Claude-Session: https://claude.ai/code/session_...` link; the text is configurable per repo (https://til.magmalabs.io/posts/9d0f1a16a1-you-can-disable-ai-attribution-in-claude-code-commits.md, accessed 2026-10-02). The Linux kernel's AI policy uses `Assisted-by:` instead. An IETF draft, draft-morrison-identity-attributed-commits (https://datatracker.ietf.org/doc/draft-morrison-identity-attributed-commits/, blocked, UNVERIFIED), argues trailers are an informal convention and proposes identity-bound attribution. Pedigree (hackathon project) wraps model id, skill hashes, prompt hash, risk class and human approver into an in-toto predicate stored in git attestation refs (UNVERIFIED).

## What to borrow

- **PROV as the vocabulary, not the storage.** Fold's log stays the source of truth; PROV is a projection computed by a pure function from events, which keeps the export deterministic and testable the same way `fold verify` is.
- **Qualified attribution.** Fold's three-party attribution (engineer, agent, session) is exactly `prov:qualifiedAttribution` + `prov:actedOnBehalfOf`: the SoftwareAgent (runner, model id) acted on behalf of the Person (owner at write time), within an Activity (the session turn).
- **in-toto Statement with the commit as subject.** Bind the session head hash and the approval ids to the commit digest in the standard envelope so GitHub's `gh attestation verify`, policy engines and SLSA tooling can consume it without learning Fold.
- **Occasio's "subject = chain head" trick.** The attestation subject digest is the last event id; verification re-walks the chain. Fold's `ledger.verify()` already does the walk.
- **Trailers for the human-readable link, attestations for the machine-checkable one.** Keep both; they serve different readers.

## What is unsolved

- **Attribution ≠ authorship.** PROV attributes an Entity to an Agent but has no notion of a quorum. Fold's "two distinct humans approved the hash" has to be modelled as two qualifiedAssociations with `hadRole fold:approver` and `hadPlan` = the approval id; nothing standard says "at least k".
- **Compaction loses PROV granularity.** A level-n summary `wasDerivedFrom` n-1 entries is representable, but which parts of the summary came from which author is not; PROV has no partial derivation. Fold's conflict entries (two active entries, same key) map to `prov:alternateOf`, which carries no "unresolved" semantics.
- **Agent identity.** Sigstore binds a human OIDC identity; the runner has none. Signing the attestation with the project host's key says "Fold vouches", not "this model vouches". Occasio and Pedigree both sidestep this by signing as the CI identity.
- **Trailers are unsigned text.** A `Fold-Session:` trailer is only as trustworthy as the commit signature plus the attestation it points to. The IETF draft exists because of this gap; no consensus yet.
- **Platform trust stores.** gitsign signatures do not show as verified on GitHub; SSH signing does but has no transparency log.

## Concrete recommendations for Fold

1. **Define the PROV mapping as a pure projection** in a new `packages/kernel/src/prov.ts`: session → `prov:Bundle`; each `SessionEvent` → `prov:Entity` with `prov:wasAttributedTo` actor and `prov:wasGeneratedBy` the turn Activity; tool call events → `prov:Activity` with `used`/`generated` workspace blobs; fork → child checkpoint `prov:wasDerivedFrom` parent checkpoint (qualified as `prov:Revision`); merge → Activity `used` base, left, right, `generated` tree; approval votes → `prov:qualifiedAssociation` with `hadRole fold:approver`, `hadPlan <approvalId>`; `MemoryEntry` → Entity, `qualifiedAttribution` to Person (userId) and SoftwareAgent (agentId), SoftwareAgent `actedOnBehalfOf` Person, `supersedes` → `wasRevisionOf`, `derivedFrom` → `wasDerivedFrom`, `retracts` → `wasInvalidatedBy`, `commitSha` → `hadPrimarySource git:<sha>`, `evidence` → `used`. Property-test it the way intent composition is tested: projection of `fold(events)` equals projection of `fold(tail, fold(prefix))`.
2. **Add `fold export --prov <log.json>`** to `packages/cli/src/main.ts`, emitting PROV-JSONLD with a `fold:` context; a `--format prov-json` flag for the 2013 encoding. Memory exports go through `packages/memory/src/store.ts` with the same mapping.
3. **Emit an in-toto Statement v1 per commit** with `predicateType: https://fold.dev/attestation/session/v1`, subjects = the commit (`gitCommit` sha1 and sha256 digests) and `fold:session:<id>` whose digest is the head event id. Predicate: session id, branch, head hash, model id, directive ids in force, approval ids with voter user ids and risk class, memory entry ids read and written. Types live in `packages/protocol/src/index.ts` next to `SessionEvent`; the builder in `packages/runner/src/tools.ts` where the commit tool runs. Sign with DSSE using the project host key (`packages/server/src/projectHost.ts`), Sigstore keyless as a later option.
4. **Standardise the trailers** the runner writes: `Fold-Session: <url>`, `Fold-Event: <head hash>`, `Approved-By: <name> <email>` one per approver, and `Co-Authored-By`/`Assisted-By` per repo policy (make the token configurable, mirroring Claude Code's `attribution` setting). Write them with `git commit --trailer` and `trailer.*.ifExists=addIfDifferent` so humans editing the message cannot duplicate them. Lives in `packages/runner/src/tools.ts`.
5. **Store attestations in `refs/attestations/commits`** (the convention Pedigree and gitsign-attest use; UNVERIFIED as to exact ref name) and let `fold verify` take a repo path: for each commit with a `Fold-Event` trailer, find the attestation, check the DSSE signature, re-walk the log to the head hash, and confirm the approval ids in the predicate match approval events in the log. Add to `packages/kernel/src/log.ts` verify path and `packages/cli/src/main.ts`.
6. **Extend `Attribution`** in `packages/memory/src/events.ts` with `eventId` (the `memory.remember` tool-call event) and `approvalId?` so an entry can point at the exact log position and, for commit-trust entries, the approval that let the commit happen. Surface it in the UI as the existing quiet "added by Ana · session billing-42 · commit 9f3c1a" line gaining a hover with "verify" that runs the chain check; no new chrome.
