# Synthesis: gaps, contradictions, and the one experiment

Completeness critique, 2026-10-02, over the four lead syntheses and 35 research memos in this directory. Scope: a desktop-first, web-first multiplayer agent product with fleets and attributed memory; mobile second.

## What is not covered, or rests only on UNVERIFIED snippets

**1. Branches have no memo, and every memo lists them as unsolved.** Fork and merge separate Fold from Codex `thread/fork`, yet no memo researches merge semantics. `merkle-proofs-observers` has no proof shape for a merge's source branch; `log-compaction-snapshots` says branch-aware snapshot placement has no prior art; `realtime-fanout-scaling` cannot say who holds the socket during a fork; `approval-cryptography` leaves approval-under-fork to a `baseTree` field; `pricing-packaging` cannot say who pays for a forked session; `observability-otel-genai` has no span model for branches. 
**2. Where the agent runs on a desktop-first product.** `tool-sandboxing` has the Tauri shell spawning a local runner under Seatbelt; `credential-broker` has a desktop local mode keeping grants in the keychain; `local-first-offline-desktop` and `realtime-fanout-scaling` assume the runner lives on the server. No memo decides whether a laptop hosts a runner, what happens when it sleeps mid-turn, or how the crash-resumable runner story in `durable-execution-replay` applies to a machine that is simply closed. The desktop-platform synthesis never names it.

**3. Trusted time inside a replay-pure log.** `claims-leases-theory` introduces a `project.tick {wallMs}` event; `approval-cryptography` says wall-clock expiry is not replayable and uses sequence distance; `fleet-scheduling-cost` promises "no wall clock"; `merkle-proofs-observers` and `compliance-evidence-export` both want an external timestamp over the chain head for auditors. Ticks arriving out of order across hosts are an open question in the kernel synthesis. No memo surveys RFC 3161 time-stamping, Roughtime or how transparency logs separate "sequenced at" from "happened at".

**4. Injection through teammates, workspace and memory, and whether the model obeys a contention at all.** `desktop-security-threats` is cited entirely from memory (every source UNVERIFIED) and calls detection unsolved. `model-context-rendering` says no public benchmark measures a model honouring a scope restriction added mid-session by a second human, and the Compliance Gap result (UNVERIFIED) suggests text alone fails. Attributed memory as a persistent injection channel is raised and never addressed. The product's safety sentence has no measurement behind it.

**5. Streaming is assumed by the UI memos and absent from the kernel memos.** `accessibility-streaming-chat` and `typography-reading-agent-text` design for token deltas; the protocol records whole model outputs as events and `harness-adapters` notes Codex emits `agentMessage/delta`. Nobody defines whether deltas become events, how a partial output hashes into the chain, or how fan-out and the Merkle tree treat them.

**6. The approval id is defined four times.** `approval-cryptography` puts `{sessionId, branch, baseTree, policyHash, call, nonce, exp}` in the digest; `tool-sandboxing` adds `sandboxProfileHash`; `desktop-security-threats` adds a tool-definition hash; `compliance-evidence-export` adds `policyHash` and says it must land now. Each breaks Phase 0 replay; the kernel synthesis schedules the digest for next quarter, the business synthesis schedules `policyHash` for now.

Also thin: every Tauri platform claim (passkeys from a WebView, notification actions on Windows and Linux, nested bubblewrap, updater rollback, WebKitGTK memory) is UNVERIFIED; `durable-execution-replay` is UNVERIFIED end to end; memory *retrieval* under the 24 kB budget has no memo, only compaction; agent identity is raised by three memos and owned by none; and nothing is measured: `fold()` on 50k events, idle memory, cache hit rate, conflict rate between long-running agents.

## Where memos contradict each other

- **Approve from a toast.** `desktop-notifications-tray` allows a background "Approve" action for `exec` and `external`; `tauri-vs-electron-2026` says notifications are pointers, never approvals, one "Open" button; `approval-cryptography` requires a passkey or keychain signoff per vote, which a background toast cannot perform. The desktop synthesis keeps the toast approve.
- **Approvals expire or never expire.** `approval-cryptography` and `local-first-offline-desktop` add `exp` and `expiresAfterTurns`; `competitor-claude-code-desktop` and the business synthesis say approval requests never expire. Reconcilable but unstated.
- **Who signs a web approval.** `identity-sso-device-trust` and the desktop synthesis sign web entries server-side after ID-token verification; `approval-cryptography` and the kernel synthesis have web users sign with passkeys.
- **Request layout versus hosted harness.** `model-context-rendering` reorders the Claude request into four cache-ordered layers with a recitation tail; `harness-adapters` hosts the Claude Agent SDK, which owns the request and offers no inlet for arbitrated intent beyond a prompt prefix. Kernel decisions 7 and 8 cannot both hold for the same session.
- **`withGlobalTauri`.** `keyboard-first-ux` and `auto-update-release-pipeline` branch on `window.__TAURI__`; the security and shell memos set it to `false`.
- **Slack votes.** `approval-cryptography` caps chat votes at `exec`; `slack-and-chat-ops-integration` renders quorum tallies for irreversible calls in-thread.
- **Next quarter is claimed three times**: notifications or telemetry (desktop), inbox and scrubber (design), evidence export moved from Phase 3 to Phase 1 (business), each conditioned on the same unanswered question of whether partners want live steering or replay.

## The one experiment

Run a contention-obedience trial on real multi-day logs: a second human contends a scope mid-turn, under four arms, Fold's own runner with and without guard enforcement, and the Claude Agent SDK adapter with and without the `PreToolUse` gate. Measure from the log, not the text: tool calls touching the contended scope before resolution, whether work continues elsewhere, prompt-cache hit rate across the intent change, and turn latency. It tests the thesis sentence, has no public benchmark, decides whether a hosted harness can carry arbitrated intent (and so whether Fold is a layer above harnesses or one more agent), settles guard-versus-prompt, and yields the first cost number for steered sessions. Everything else can wait a quarter.
