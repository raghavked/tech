# Compliance evidence export: EU AI Act Art. 12/14, NIST AI RMF agentic profile, SOC 2

Slug: `compliance-evidence-export`. Research date: 2026-10-02. Several primary domains (artificialintelligenceact.eu, ec.europa.eu service desk, CSA labs, OWASP AOS, arXiv, hoop.dev) are blocked by the egress proxy; those entries are marked UNVERIFIED and rest on search snippets plus the regulation text as published in OJ L 2024/1689.

## Why it matters for Fold

Fold already has the hard part: every directive, tool call, vote, role change and handoff is an event in a hash-chained log, approvals are bound to the content hash of the exact call, and `fold verify` proves chain integrity and replay determinism (`docs/05_kernel_design.md` §1, §3; `packages/kernel/src/approvals.ts`). What it lacks is the thing an auditor can take away. Auditors do not read event logs; they ask three questions per privileged action: who caused it, who authorised it, and under which rule. Today the answer is spread across `agent.tool.requested`, `approval.requested`, `approval.voted`, `role.changed` and a `SessionPolicy` that is only stored at session creation (`packages/protocol/src/index.ts`, lines 98-148). A customer running agents on production infrastructure will be asked for this evidence in its next SOC 2 period, and from 2 August 2026 any customer whose agent sits inside a high-risk use case under Annex III must keep automatically generated logs for at least six months (Art. 26(6)) and show that oversight was real (Art. 14). An export that answers the three questions from the log, with a verifiable integrity proof, is cheap for Fold and expensive for every competitor whose "session" is a chat transcript.

## Prior art

1. **EU AI Act, Article 12 (record-keeping)**, OJ L 2024/1689. High-risk systems must "technically allow for the automatic recording of events (logs) over the lifetime of the system"; logs must support identifying risk situations and substantial modifications, post-market monitoring, and monitoring of operation. For biometric systems the minimum fields are the period of each use (start and end), the reference database, matched input data, and "the identification of the natural persons involved in the verification of the results". Article 19 (providers) and Article 26(6) (deployers) set a six-month minimum retention. https://artificialintelligenceact.eu/article/12/ (accessed 2026-10-02, snippet only; UNVERIFIED fetch).
2. **EU AI Act, Article 14 (human oversight)**. Systems must be designed so natural persons can oversee them; the overseer must be able to understand capacities and limitations, remain aware of automation bias (14(4)(b)), correctly interpret output, decide not to use or to disregard, override or reverse an output, and "intervene ... or interrupt the system through a 'stop' button or similar procedure" (14(4)(e)). https://artificialintelligenceact.eu/article/14/ (accessed 2026-10-02; UNVERIFIED fetch, text from the OJ consolidated version).
3. **CSA, "Agentic AI Profile for the NIST AI RMF" v1 (draft, 2026-03-27)**. Extends Govern/Map/Measure/Manage with autonomy-tier classification and corresponding oversight obligations, tool-use risk modelling, runtime behavioural governance and delegation-chain accountability. The companion research note cites that only 38% of organisations monitor prompts, tool calls and outputs end to end. https://labs.cloudsecurityalliance.org/agentic/agentic-nist-ai-rmf-profile-v1/ (accessed 2026-10-02; UNVERIFIED).
4. **SOC 2 for agentic AI** (hoop.dev guide; mintmcp "SOC 2 AI agents"; nhimg.org FAQ). Recurring auditor findings: privileged actions must trace to an identifiable person, a shared API key is not attribution; auditors request three evidence categories, governance artefacts (policies, risk assessments), enforcement proof (gateway and policy definitions) and operational records (logs, traces, change approvals); the standing question is "Why did the agent take this action? Was it authorised?" https://hoop.dev/blog/soc-2-for-agentic-ai-a-compliance-guide/ and https://www.mintmcp.com/blog/soc-2-ai-agents (accessed 2026-10-02; UNVERIFIED).
5. **OWASP Agent Observability Standard (AOS), "Extend OCSF"**. Maps agent events onto OCSF API Activity class 6003 so SIEMs ingest them unchanged; OCSF is a Linux Foundation project and was put forward for ITU ratification in 2025/26. https://aos.owasp.org/spec/trace/extend_ocsf/ (accessed 2026-10-02; UNVERIFIED).
6. **in-toto attestation framework v1 / DSSE envelope**. Four layers: predicate, statement (binds subject digests to a predicate type), envelope (DSSE, `payloadType: application/vnd.in-toto+json`), bundle. CNCF graduated; underpins SLSA and GitHub artifact attestations. https://github.com/in-toto/attestation/blob/main/spec/v1/envelope.md (accessed 2026-10-02).
7. **NovaFabric: tamper-evident, replayable evidence for autonomous AI agent runs** (arXiv 2609.12582, September 2026). `nova export-evidence` produces one archive: a byte-equal run capsule, lineage subgraph, referenced JSON schemas, a manifest hashing every artefact, and three in-toto statements (run, redaction, lineage) in DSSE envelopes. Closest existing design to what Fold needs. https://arxiv.org/abs/2609.12582 (accessed 2026-10-02; UNVERIFIED, abstract snippet).

## What to borrow

- **The three-question record.** Collapse the event graph into one flat *action record* per tool call: who requested (agent, in which turn, under which composed intent), who approved (named humans, their rank at the time, vote time, reason), under which policy (policy hash, rule for the risk class). This is the row auditors want; the log stays the proof.
- **Article 12's biometric minimum as a template.** Period of use, input, match, and the natural persons who verified. Fold's analogue: session start/end, tool input hash, tool output hash, voter identities.
- **Article 14(4)(e) as an evidence category.** Pauses, cancels and denies are oversight events, not failures; export them with the same prominence as approvals. Shadowed directives are evidence against automation bias: a human said something and it was recorded even though it did not apply.
- **NovaFabric's bundle shape.** Manifest with per-file digests, a redaction attestation separate from the run attestation, and verifiable in-toto statements. Fold already has `sha256Hex` and canonical JSON (`packages/kernel/src/hash.ts`); a DSSE envelope is a few lines on top.
- **OCSF projection.** Do not make OCSF the native format; emit it as a projection so customers' SIEM retention policies cover Fold without new tooling.

## What is unsolved

- **Applicability.** Fold is a general tool; whether Article 12 applies depends on the customer's use case. The export must not claim conformity, only supply the records.
- **Policy provenance.** Approvals are bound to the hash of the call, not to the hash of the policy under which the rule was chosen. A policy edit between request and vote is currently invisible.
- **Identity strength.** Phase 0 authentication is a shared token (`docs/05_kernel_design.md` §"deliberately simple"). "Approved by whom" is only as good as the identity provider behind `actorId`.
- **Secrets and PII in tool I/O.** Tool outputs contain credentials and customer data; auditors must see enough to verify, not everything. Redaction must itself be attested so the hash chain still verifies.
- **Retention versus memory compaction.** Team memory compacts (`docs/14_organisation_memory.md`); the session log must not. Six months is a floor, not a target.
- **Time.** Timestamps are the server's. A regulator may want an external timestamp over the chain head.

## Concrete recommendations for Fold

1. **Add `policy.changed` and a `policyHash` on `approval.requested`** in `packages/protocol/src/index.ts`, and have `packages/kernel/src/approvals.ts` compute `ruleFor` against the policy identified by that hash. The approval id then commits to call hash plus policy hash. Add an optional `reason: string` to `approval.voted`; Article 14 asks for the reason behind an override.
2. **Create `packages/kernel/src/evidence.ts`** exporting `actionRecords(state): ActionRecord[]`, a pure fold over the log. Fields: `sessionId`, `branch`, `seq`, `turn`, `callHash`, `tool`, `riskClass`, `requestedAt`, `completedAt`, `outcome`, `inputDigest`, `outputDigest`, `intent` (goal and active steers at the epoch), `policyHash`, `rule`, `votes[] {actorId, role, rank, vote, at, reason}`, `oversight[]` (pauses, cancels, denies, shadowed directives in the same epoch), `participantsPresent[]`. Same package, same determinism tests as `brief.ts`.
3. **Add `fold export-evidence <log.json> --from --to --redact <profile>`** in `packages/cli/src/main.ts`, next to `verify`. Output is a zip: `manifest.json` (every file with sha256), `records.jsonl`, `events.jsonl` (byte-equal log slice), `policies.json` (every policy version seen), `participants.json` (role timeline from `participant.joined`/`role.changed`), `verify.json` (chain and replay result), `records.ocsf.jsonl` (projection to API Activity 6003), and `attestations/*.dsse.json`: three in-toto statements (run, redaction, verify) signed with the server key. Subject digests are the chain head hash and the manifest hash.
4. **Fleet and memory scope.** Mirror the command on the project ledger (`packages/fleet/src/ledger.ts`, `verify()` already exists) so claims, lead directives and contentions export with the same record shape, and let `packages/memory/src/store.ts` export an entry's attribution (engineer, session, commit) as a record so a memory fact can be traced to the action that produced it.
5. **Retention and server storage.** In `packages/server/src/storage.ts` make session logs append-only with a configurable minimum retention (default 6 months, never below) independent of memory compaction, and expose `GET /sessions/:id/evidence` with the same output as the CLI.
6. **Interface, kept quiet.** One entry, "Export evidence", in the session menu in `apps/web`, producing the zip. No dashboard. In the conversation column, an approved irreversible call's collapsed tool line gains a one-word trailer, "approved by Ana, Ben", in the muted token colour from `design/tokens.css`, so oversight is visible in place without a new surface.
