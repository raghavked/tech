# Claims and leases for many agents on one repository

Research memo, 2026-10-02. Slug: `claims-leases-theory`. Verification note: the egress proxy blocked every primary source (USENIX, Google Research, Kleppmann, Apache, three university mirrors). Statements about Chubby, ZooKeeper, Omega and Kleppmann are reconstructed from search snippets plus background knowledge and are marked UNVERIFIED where a number or quote could not be checked. The dibs README was fetched and is verified.

## Why it matters for Henosis

Henosis's fleet layer already has a lease model: `ClaimRecord` in `packages/fleet/src/claims.ts` holds a resource (path prefix, service, ticket), a mode (exclusive/shared), a `requestedSeq`, a status and a `lastTouchedTurn`; `Project.claim` in `packages/fleet/src/project.ts` grants deterministically (first active holder wins), `expireStale` expires by holder-turn inactivity, and the guard (`canWrite`) turns a held path into a tool result the model can read. Two things make this different from a datacentre lock service. The lease holder is a *session* whose principal is a *human engineer*, and the arbiter is not a quorum of servers but a hash-chained event log that every replica replays. That second point is why the repo chose turns over wall clock for TTL, and it is also why the classic failure modes (stale holders, herds, starvation, all-or-nothing denials) show up in slightly different clothes. Three present gaps are concrete: `claimTtlTurns` defaults to `0` in `packages/fleet/src/state.ts` (expiry is off), `status: "pending"` exists on the record but nothing queues or grants from it, and `docs/13_fleet_collaboration.md` itself lists partial admission as not implemented.

## Prior art

1. **Chubby (Burrows, OSDI 2006).** https://static.usenix.org/events/osdi06/tech/full_papers/burrows/burrows_html (accessed 2026-10-02, blocked; snippet via research.google). Coarse-grained, advisory locks on a file-system namespace, chosen over a Paxos library because "developers do not plan for availability" and a lock service lets them add coordination late. Two ideas matter here. A **sequencer** is a byte string naming the lock, its mode and a lock generation number; a holder passes it to the services it talks to, and those services call `CheckSequencer` (or compare generations) so a request made under a lost lock is rejected. **Lock-delay** is the complement for services that cannot check: when a lock is freed by failure rather than release, Chubby refuses to grant it to anyone else for a holder-chosen period (UNVERIFIED: bounded at about one minute). Sessions are leases renewed by KeepAlives, with a grace period ("jeopardy") during which the client blocks rather than assumes loss (UNVERIFIED: 12 s lease, 45 s grace).
2. **ZooKeeper lock recipes.** https://zookeeper.apache.org/doc/current/recipes.html (accessed 2026-10-02, blocked; snippet verified the recipe steps). A waiter creates an ephemeral, sequential znode; the lowest sequence holds the lock; each waiter watches only the next-lowest node, which is what avoids the **herd effect**. Ephemerals vanish with the session, so liveness is bound to session liveness rather than a separate TTL. The shared-lock recipe has readers watch the nearest *write* node and writers watch the nearest node of any kind, which is a FIFO, phase-fair ordering.
3. **Omega (Schwarzkopf, Konwinski, Abd-El-Malek, Wilkes, EuroSys 2013).** https://cs.brown.edu/~malte/pub/papers/2013-eurosys-omega.pdf (accessed 2026-10-02, blocked; snippet via research.google). Many schedulers work on private copies of one shared cell state and commit with optimistic concurrency; the master accepts a transaction only if the resources it touches have not changed. A scheduler chooses **all-or-nothing** or **incremental** transactions: incremental keeps the non-conflicting part and retries the rest. Fine-grained conflict detection (per-machine sequence numbers) rather than "anything on the machine changed" cut conflict rates substantially (UNVERIFIED: paper's figure). Fairness is not built into the state store; it is left to scheduler policy and preemption.
4. **Kleppmann, "How to do distributed locking" (2016).** https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html (accessed 2026-10-02, blocked; argument confirmed by several secondary sources in the search). A lease with a timeout cannot give mutual exclusion alone: a GC pause lets the lease lapse while the holder still believes it holds it. The fix is a **fencing token**, a monotonically increasing number issued with the lease and checked by the resource, not the client. He distinguishes locks for *efficiency* (duplicate work is fine) from locks for *correctness* (duplicate work corrupts).
5. **Brandenburg and Anderson, phase-fair reader-writer locks** (via arXiv 1909.09600 survey and 1309.4507). https://arxiv.org/pdf/1909.09600 (accessed 2026-10-02, snippet). Reader-preference locks starve writers under frequent reads; phase-fair locks alternate reader and writer phases so neither class waits more than one phase.
6. **dibs (polymatx).** https://github.com/polymatx/dibs (accessed 2026-10-02, verified). File claims for coding agents: doublestar globs, default TTL 30 m and max 24 h, exclusive only, expiry "evaluated lazily at read time", conservative overlap ("two globs whose static prefixes are nested are treated as conflicting"), and denials phrased for the model: "denied... src/auth/token.go held by alice (refactor auth), expires in 29m." A Claude Code hook blocks the edit (exit 2) and a git pre-commit hook is the second line.

## What to borrow

- **Fencing on every guarded write.** Henosis's guard consults current state at write time, which is fine for a live runner, but the crash-resumable runner (`packages/runner/src/runner.ts`) finishes a dead runner's tool calls, possibly after the claim expired or was released by a lead's resolution. A claim generation checked at the write is the Chubby sequencer / Kleppmann token, and it costs one integer.
- **Lock-delay after involuntary expiry.** When a claim lapses because the holder went quiet, do not hand the path to the next session at once; hold it for the former holder for a short grace, and tell its owner. This is the Chubby grace period transposed to a human-fronted session.
- **Waiter queue by sequence, notify one.** `requestedSeq` already gives a ZooKeeper-style order. Granting the lowest pending claim on release, and notifying only that session, avoids both the herd and the "retry the claim every turn" behaviour an agent will otherwise learn.
- **Incremental admission.** Omega's incremental transaction is exactly partial admission: a multi-resource claim is granted for what is free and denied for the rest, with holders listed, so the agent can start on the free part.
- **Model-readable denials.** dibs' denial string (holder, reason, expiry) is the right payload; Henosis already routes denials to both owners and the lead, which is the part dibs lacks.

## What is unsolved

- **Turn TTL versus wall clock.** Turns keep replay pure, but a paused or stalled session never advances its turn and so never expires, which is the opposite of what a lease is for. Wall-clock expiry is impure unless the clock reading is itself an event. Nobody in the prior art has this problem because none of them replays.
- **Fairness with human principals.** Omega and ZooKeeper assume symmetric clients. In Henosis a lead outranks owners, and "first active holder wins" plus a FIFO queue can still starve a junior engineer's session behind a senior's long refactor. Age-based escalation to the lead is a policy, not a theorem.
- **Shared mode is under-specified.** With shared claims permitted, writer starvation (an exclusive waiter behind a stream of shared readers) is a real risk; phase-fairness is the known answer but interacts with lead rank.
- **Advisory edges.** The guard is mandatory for tool writes but humans editing in a worktree and merges (`packages/kernel/src/merge.ts`) bypass it; the merge-conflict contention catches it late.

## Concrete recommendations for Henosis

1. **Add `generation` to `ClaimRecord` and fence the guard** (`packages/fleet/src/claims.ts`, `project.ts`). Increment on every `claim.granted`; have `canWrite(sessionId, path, claimGen?)` return `{ok:false, reason:"stale"}` when the caller's generation differs. Thread the generation through the tool call payload in `packages/runner/src/tools.ts` so a resumed runner fails closed.
2. **Replace `claimTtlTurns: 0` with a hybrid tick** (`packages/fleet/src/state.ts`, `project.ts`). Have the project host (`packages/server/src/projectHost.ts`) emit a `project.tick {wallMs}` event at a fixed cadence; `expireStale` reads ticks and holder turns from the log, so expiry stays replayable while a stalled session still expires. Default: 30 holder turns or 20 ticks of 1 minute, whichever first.
3. **Add a `lapsed` grace state** (`project.ts`, `events.ts`). Involuntary expiry moves a claim to `lapsed` for `claimGraceTurns` (default 3 ticks); the former holder's `session.report` re-activates it, otherwise it becomes `expired`. Emit a quiet notice to the owner's session in the register of an approval notice.
4. **Make `pending` real: FIFO grant on release, single-waiter notify** (`project.ts` `release`, `expireStale`, `resolve`). Denied claims stay `pending` ordered by `requestedSeq`; on any release or expiry of an overlapping claim, grant the lowest compatible pending claim and mirror a `claim.granted` into only that session. Add phase-fairness: while an exclusive claim is pending, refuse new shared grants on the same resource.
5. **Partial admission** (`claims.ts` `partitionClaim`, `project.ts` `claim`). Accept `resources: Resource[]`; return `{granted, denied:[{resource, holders}]}` and emit one `claim.granted` for the free subset and one `claim.denied` per blocked resource, so the agent proceeds on the free part. Record this in `docs/13_fleet_collaboration.md` where partial admission is listed as missing.
6. **Age-based contention escalation** (`packages/fleet/src/contention.ts`, `brief.ts`). A pending claim older than `N` ticks raises its contention to the lead and appears in the fleet brief under "waiting", which bounds starvation by human intervention rather than by rank.
7. **Second line of enforcement for humans** (`packages/cli/src`). A `fold hook pre-commit` that calls `canWrite` for staged paths, mirroring dibs' git hook, with a warning not a block for owners editing their own held paths.
