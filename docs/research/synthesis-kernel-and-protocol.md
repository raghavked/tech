# Synthesis: kernel and protocol

Lead-architect synthesis, 2026-10-02. Theme: `kernel-and-protocol`. Inputs: twelve memos under `scratchpad/research100/`, `docs/04_technical_architecture.md`, `docs/06_roadmap.md`. Desktop first, web alongside, mobile secondary; each decision is judged by what it makes true for a Tauri shell and a browser folding the same log.

The thread through the memos is one line from the architecture doc: clients never receive derived state, they derive it. That holds today for one reducer version, one small log, one trusted server and one runner. The decisions below keep it true as each changes.

## Decisions

**1. Stamp every event with a kernel version and witness state at turn boundaries.** Add `v: { schema, kernel, runner? }` to `SessionEvent`, a `kernel.upgraded { from, to }` marker the reducer consults for rule selection, and `stateHash` on `agent.turn.ended` and `checkpoint.created`. A replay corpus under `packages/kernel/test/fixtures/logs/` gates CI on head hashes. Evidence: `durable-execution-replay`, `log-compaction-snapshots` (REDUCER_VERSION). Changes: `packages/protocol/src/index.ts`, `packages/kernel/src/log.ts` (`SerializedChain.version` 1 to 2 with a defaulting loader), `state.ts`, `replay.ts`, `packages/cli` `fold verify`. Phase: now; it is a prerequisite for decisions 3 and 6. Risk: a hand-bumped version is forgotten; the corpus only catches it if a fixture is added per release.

**2. Add a Merkle tree beside the chain and make the desktop a skeptical client.** `packages/kernel/src/merkle.ts` implements RFC 9162 over the existing event ids; `ChainLog` keeps a `1 + log2 n` frontier per branch; the wire gains `resume`, `checkpoint {origin, size, root, signatures[]}` and `consistency`. The desktop shell keeps its `(branch, size, root)` anchor in a file and refuses to fold until the consistency proof checks. Evidence: `merkle-proofs-observers`, `log-compaction-snapshots`. Changes: `kernel/src/merkle.ts` (new), `log.ts`, `protocol`, `apps/web/src/sync.ts` (new), `apps/desktop`. Phase: tree and proofs now; signed checkpoints and CLI/Slack witnesses next quarter. Risk: a server-signed checkpoint proves nothing against the server, and a merge has no proof shape for its source branch; put the source root in the merge payload and treat cosigning as the real fix.

**3. Delta join, JSONL per branch, sidecar snapshots, blob-backed payloads.** `join` carries the client's last `(branch, seq, hash)`; the server appends `events/<branch>.jsonl` per event and writes `snapshots/<branch>/<seq>.json` every 500 events and at every checkpoint so forks inherit one. Snapshots carry the kernel version from decision 1. Tool outputs over 64 KB move to the blob store with `{ blob, bytes, preview }` in the event. `session.rolled` is the continue-as-new boundary at 10,000 events. Evidence: `log-compaction-snapshots`, `durable-execution-replay`. Changes: `packages/server/src/storage.ts`, `host.ts`, `protocol`, `packages/runner`, `apps/web/src/cache.ts` (new, IndexedDB with try/catch fallback). Phase: now. Risk: until decision 2 lands an observer trusts the server's snapshot and the UI must say so; branch-aware snapshot placement has no prior art.

**4. Make approvals cryptographic: digest, signoff, fail-closed predicate.** `approvalDigest = sha256(canonical({sessionId, branch, baseTree, policyHash, call, nonce, exp}))` becomes the approval id; `approval.voted` carries a signoff over the digest; `evaluate` checks digest, signature, distinct credential and actor, rank, seq-based expiry, then threshold, and stays `pending` otherwise. A grant is consumed by one `tool.started`; `branch` and `baseTree` in the digest settle open question 7. Desktop and CLI sign with a device-bound ed25519 key in the OS keychain; web uses passkeys. Evidence: `approval-cryptography`, `provenance-standards` (DSSE), `harness-adapters` (post-rewrite hash). Changes: `kernel/src/hash.ts`, `session.ts`, `approvals.ts`, `protocol`, `packages/server` as notary, `apps/desktop`, `packages/cli`. Phase: next quarter, behind the roadmap's identity work. Risk: what-you-see-is-what-you-sign is unsolved on every passkey platform; passkeys from `tauri://` are untested.

**5. Write the arbitration reference model and fix the three non-commutative cases.** Add `packages/kernel/test/intent.model.ts` (priority-ordered MV-register per scope, G-Set constraints, control lattice) and `fast-check` properties for commutativity, idempotence, status monotonicity and one-active-xor-one-contention. Freeze `driverAtSubmission` on the record, make control a lattice (`cancelled > paused > running` within an epoch), make contention freezes sticky and re-stamp merged directives with the merge epoch. Evidence: `intent-arbitration-formal`. Changes: `kernel/src/intent.ts`, `protocol`, `kernel/package.json`, `docs/05_kernel_design.md`. Phase: tests and `driverAtSubmission` now; lattice and sticky contention next quarter. Risk: each fix changes who won in old logs, so it ships only behind a `kernel.upgraded` marker from decision 1.

**6. Fence claims and make time replayable.** Add `generation` to `ClaimRecord` and thread it through the tool call so a resumed runner fails closed; replace `claimTtlTurns: 0` with holder turns plus a `project.tick {wallMs}` event the project host appends on a cadence; add a `lapsed` grace state, FIFO grant from `pending` with single-waiter notify, and partial admission. Evidence: `claims-leases-theory`, `fleet-scheduling-cost`. Changes: `packages/fleet/src/claims.ts`, `project.ts`, `state.ts`, `events.ts`, `packages/server/src/projectHost.ts`, `packages/runner/src/tools.ts`. Phase: generation and tick now; queue, grace and partial admission next quarter. Risk: the tick is the ledger's first wall-clock reading, pure only because it is an event; fairness between lead and junior stays policy.

**7. Enforce in the guard what the prompt only asks for.** Contended scopes become tool refusals in `WorkspaceGuard`, journaled with the intent's wording. Reorder the Claude request into four cache-ordered layers with breakpoints, append a 300-byte recitation tail, and record a `ContextRender` event with byte budgets and cache counters. Evidence: `model-context-rendering`. Changes: `packages/runner/src/tools.ts`, `claude.ts`, `runner.ts`, `protocol`. Phase: now. Risk: intent updates and cache hits are in tension; only measurement finds the cutover.

**8. Host other harnesses through one adapter contract that defers rather than blocks.** `packages/runner/src/harness.ts` defines `onToolProposed -> allow | deny | defer`, `suspend -> OpaqueSnapshot`, `resume`, `fork`; the protocol gains `HarnessSuspended` and `StandingApproval` events. The Claude Agent SDK adapter gates on a `PreToolUse` hook and binds the approval to the post-`updatedInput` hash; Codex, OpenAI Agents and LangGraph follow, with a conformance suite asserting one Fold event sequence from each. Evidence: `harness-adapters`. Changes: `packages/runner/src/harness.ts`, `claude.ts`, `codex.ts`, `openai.ts`, `langgraph.ts` (new), `packages/runner/test/harness-conformance.test.ts`. Phase: next quarter, matching roadmap Phase 1. Risk: determinism stops at the opaque blob and every harness hides steps; the client's fidelity badge is not optional.

**9. Add a symbol resource and a pure extractor, recorded as events.** `Resource` gains `symbol { path, name, kind }`; new `packages/semantics` wraps `web-tree-sitter` with pinned WASM grammars; the guard refuses only tier 1 (same symbol or migration number), warns on reachability, ignores dataflow. The verdict is a `SymbolsObserved` event so verify replays it rather than re-parsing. Evidence: `semantic-conflict-detection`, `claims-leases-theory` (partial admission). Changes: `packages/fleet/src/events.ts`, `claims.ts`, `packages/semantics` (new), `packages/runner/src/tools.ts`. Phase: later, after decision 6. Risk: published dataflow detectors run at 26% false positives; promote a tier only above 0.9 replayed precision.

**10. Make memory compaction provable per claim.** `Summarizer` returns `{ claims: { text, from[] } }`; `compact()` rejects a fold that cites outside its candidates or leaks a retracted value; folds read level-0 originals, depth caps at 2; a deterministic gate and an offline probe suite score every summariser against `bulletSummarizer`. Evidence: `memory-compaction-quality`, `provenance-standards`. Changes: `packages/memory/src/store.ts`, `events.ts`, `curator.ts`, `eval.ts` (new). Phase: next quarter. Risk: no faithfulness metric clears 70% on hard cases; the deterministic checks carry the weight.

**11. Export provenance as a pure projection, and bind commits to the log head.** `packages/kernel/src/prov.ts` maps events to PROV-O; `fold export --prov` emits PROV-JSONLD; the runner writes `Fold-Session`, `Fold-Event` and `Approved-By` trailers and a host-signed in-toto Statement whose subject digest is the head event id. Evidence: `provenance-standards`, `merkle-proofs-observers`, `approval-cryptography`. Changes: `kernel/src/prov.ts` (new), `packages/cli/src/main.ts`, `packages/runner/src/tools.ts`. Phase: trailers now (cheap, visible); projection and attestation later, with roadmap Phase 3. Risk: PROV cannot say "at least k approvers"; a host-signed attestation says Fold vouches, not the model.

## Sequencing

Now: 1, 3, 7, tests from 5, fencing from 6, trailers from 11. Next quarter: 2 (signing), 4, rest of 5 and 6, 8, 10. Later: 9, rest of 11. Decision 1 gates every change to old-log semantics; decision 2 gates any claim that the desktop sees the real session.

## What we still do not know

1. Whether `stateHash` witnesses survive a reducer change that is a bug fix rather than a rule change, or whether every fix needs a marker.
2. How to prove a merge's source branch to a client that only verified the target.
3. Whether `navigator.credentials` works from a Tauri WebView against a hosted rpId on all three desktop platforms.
4. What the human actually signed when the client that rendered the call is compromised.
5. Where snapshots should sit on a branch tree so both parent and fork can use them.
6. Whether a wall-clock tick event stays acceptable to `fold verify` once ticks arrive out of order across hosts.
7. The real semantic conflict rate between long-running agents under claims; CodeCRDT's 5-10% is from short tasks.
8. How often a changed intent misses the prompt cache in practice, and whether the 20-block lookback covers it.
9. Whether any harness will expose enough to make the fidelity badge read "complete".
10. Who paid when a forked session's handoff is accepted by a third engineer.
