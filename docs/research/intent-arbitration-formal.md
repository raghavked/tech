# Intent arbitration as a formal object: what Henosis can prove, and what its tests should assert

Research memo, 2026-10-02. Scope: `packages/kernel/src/intent.ts`, `packages/kernel/test/intent.test.ts`, `docs/05_kernel_design.md` section 2. Egress to arXiv, ACM, Wikipedia and the authors' sites was blocked; all prior-art claims below come from search snippets and prior knowledge and are marked UNVERIFIED.

## Why it matters for Henosis

Henosis's pitch rests on one sentence in the kernel design: "within an epoch the composed intent does not depend on the arrival order of directives from different authors." That is the property that lets every surface (desktop, web, mobile) render the same goal, steers, constraints and contentions from the same log without asking a server which human "won." If it is only approximately true, a contributor who races the sequencer can beat a peer, a replay after a driver-token transfer can flip a directive from active to contended, and the "quiet notice" for a contention in the UI can lie. The current proof is a 300-interleaving randomised test. That is a good smoke test, not a specification. This memo names the algebraic object the arbiter already is, the properties it should satisfy, and where the implementation departs from them.

## Prior art

1. Sun, Jia, Zhang, Yang, Chen, "Achieving convergence, causality-preservation and intention-preservation in real-time cooperative editing systems," ACM TOCHI 5(1), 1998. https://dl.acm.org/doi/10.1145/274444.274447 (accessed 2026-10-02, snippet only, UNVERIFIED). The CCI model. Key insight for Henosis: convergence can always be bought with serialisation; intention preservation cannot, because a serialised operation applied to a state it was not generated against does something its author did not mean.
2. Shapiro, Preguiça, Baquero, Zawirski, "A comprehensive study of Convergent and Commutative Replicated Data Types," INRIA RR-7506, 2011. https://hal.inria.fr/inria-00555588 (accessed 2026-10-02, UNVERIFIED). Defines G-Set, LWW-register and MV-register, and the join-semilattice condition (commutative, associative, idempotent merge) under which replicas converge.
3. Gomes, Kleppmann, Mulligan, Beresford, "Verifying strong eventual consistency in distributed systems," OOPSLA 2017. https://arxiv.org/abs/1707.01747 (accessed 2026-10-02, UNVERIFIED). The abstract convergence theorem: if every pair of concurrent operations commutes and operations stay valid under every permitted delivery order, all replicas that saw the same set of operations are in the same state. Mechanised in Isabelle; the AFP entry is https://www.isa-afp.org/entries/CRDT.html.
4. Burckhardt, Gotsman, Yang, Zawirski, "Replicated data types: specification, verification, optimality," POPL 2014. https://dl.acm.org/doi/10.1145/2535838.2535848 (accessed 2026-10-02, UNVERIFIED). Specifies a data type as a function from a visibility/arbitration relation over events to a return value. This is the right shape for Henosis's spec: the arbiter is a function of (visibility = log prefix, arbitration = rank then epoch then author).
5. Baquero, Almeida, Shoker, "Pure operation-based replicated data types," arXiv 1710.04469, 2017. https://arxiv.org/abs/1710.04469 (accessed 2026-10-02, UNVERIFIED). A partially ordered log (PO-Log) of operations, a query function that computes the value from the log, and causal stability as the licence to compact. Henosis's directive list plus `arbitrate()` is a PO-Log plus query; the epoch is a stability oracle.
6. Kleppmann, Gomes, Mulligan, Beresford, "Interleaving anomalies in collaborative text editors," PaPoC 2019. https://martin.kleppmann.com/2019/03/25/papoc-interleaving-anomalies.html (accessed 2026-10-02, UNVERIFIED). Convergent algorithms that produce outputs no user intended; convergence proofs need an explicit statement of what counts as a preserved intention.

## What to borrow

**Name the object.** Henosis is not a CRDT in the replication sense: the hash-chained log is a single total order, so replica convergence is trivial (a deterministic fold over the same prefix). What Henosis wants is *commutativity of the fold under a concurrency relation*. Define `d1 ∥ d2` iff same scope, different author, and (same epoch, or either is merged). The claim to prove is: for any log `L` and any permutation `π` that only swaps `∥`-related pairs, `arbitrate(L) ≡ arbitrate(π(L))` up to `seq`. That is exactly the premise of the abstract convergence theorem with "concurrent" read as "same epoch."

**Per-scope register is an MV-register with a priority order.** Define `d1 ≺ d2` iff (same author and `seq1 < seq2`) or `rank1 < rank2` or (same rank, `epoch1 < epoch2`, neither merged). The register's value is the set of `≺`-maximal live directives. Singleton = active steer; size ≥ 2 = contention. Rules 1-4 in `intent.ts` are a hand-unrolled computation of this maximal set. `latest-wins` is the LWW-register degenerate case (timestamp = `seq`); `driver-wins` is a tie-break. Writing the spec this way gives a short reference model to test the implementation against.

**Constraints are a G-Set; withdrawal makes it an author-local 2P-set.** Union is commutative, associative and idempotent. Withdrawal is safe only because an author withdraws their own directive (single-writer causal order).

**Epoch is causal stability.** A directive is stable once the agent has started a turn after it. Superseded and shadowed directives in closed epochs can be compacted into the checkpoint while keeping the log; this is the PO-Log pruning argument and it keeps the brief and the replay cheap.

## What is unsolved

1. **Control is an LWW register keyed by `seq`.** Concurrent `pause` (contributor) and `resume` (driver) from peers at equal rank are order-dependent. The order-independence test passes only because its fixtures avoid the case.
2. **`driver-wins` reads the current driver, not the driver at submission.** Rank is frozen at submission; the driver token is not. A token transfer between submission and the next arbitration flips a directive's status without any directive event, so status is not monotone along the log and a replay-with-later-prefix can disagree with the live view.
3. **Concurrency is computed against the latest peer only.** With A and B contended at epoch 1 and C (same rank) arriving at epoch 2, `pickAmongPeers` declares C a redirect, marks A and B superseded, and leaves the unresolved contention object in `existing`. Two consequences: `contendedScopes` and open contentions disagree, and a contributor can dissolve a contention by waiting one turn, which the authority model says only a driver or owner may do.
4. **`merged` is a permanent flag.** A directive carried in by a merge stays concurrent with every later directive on its scope forever, so a stale branch can contend with fresh direction months later. A merged directive should be re-stamped with the merge epoch instead.
5. **Intention preservation has no statement.** The design says "when two intentions cannot both be preserved, the kernel refuses to pick," but nothing asserts that every live directive is visible with a reason, which is the only intention guarantee Henosis can actually give.

## Concrete recommendations for Henosis

1. **Write the reference model** in `packages/kernel/test/intent.model.ts`: directives, the `≺` order above, maximal-set per scope, G-Set for constraints, and a lattice for control. Use it as the oracle for differential tests against `arbitrate()`.
2. **Add property-based tests** in `packages/kernel/test/intent.properties.test.ts` (add `fast-check` to `packages/kernel` devDependencies). Assert: (a) commutativity: `arbitrate` is invariant under any permutation of `∥`-related pairs, including under `block` and `driver-wins`, and explicitly *not* under `latest-wins`; (b) idempotence: delivering a directive id twice changes nothing; (c) status monotonicity along log prefixes: `pending → active → {superseded, shadowed, contended}`, and `contended → active` only via a resolve or withdraw event; (d) invariants after every event: each scope has exactly one active steer xor one open contention; `contendedScopes` equals scopes of unresolved contentions; no shadowed or contended text appears in `renderIntent`; a higher-rank directive is never shadowed by a lower one; (e) metamorphic: adding a strictly higher-rank directive on a scope never increases that scope's contention count; withdrawing one member of a two-member contention activates the other.
3. **Make control a lattice** in `packages/kernel/src/intent.ts`: within an epoch, join is `cancelled > paused > running` among authorised authors; across epochs, later wins. This makes control commute among concurrent peers and errs toward the safer state. Document in `docs/05_kernel_design.md` table row "Control."
4. **Freeze the driver at submission.** Add `driverAtSubmission: boolean` to `DirectiveRecord` in `packages/kernel/src/intent.ts` (and the protocol type in `packages/protocol/src/index.ts`), set from `effectiveRank` at the time the event is appended, and make `driver-wins` read it. Then every status change has a log event as its cause.
5. **Make contention freezes sticky.** In `pickAmongPeers`, treat any live directive on a scope with an unresolved contention as concurrent with that contention's members regardless of epoch, until a `resolve` or `withdraw` event. Re-stamp merged directives with the merge epoch instead of the permanent `merged` flag.
6. **State intention preservation as an invariant and test it**: every non-withdrawn directive has a status, every non-active status carries a reason (superseded-by id, shadowed-by id, contention id), and the UI's quiet notice renders that reason. Put the invariant in `docs/05_kernel_design.md` next to the order-independence claim so the design and the test say the same thing.
