# Harness adapters: hosting third-party agent runs as Fold sessions

Research memo, 2026-10-02. Topic: mapping Claude Agent SDK, OpenAI Agents SDK, LangGraph and the Codex app-server onto Fold's turn, tool and approval events, and where each harness hides steps.

## Why it matters for Fold

Fold's value is the kernel: arbitrated intent, hash-bound approvals with quorum, fork and merge, replay. None of that depends on which model loop produces the tool calls. Teams already run Claude Code, Codex, OpenAI Agents and LangGraph graphs; if Fold only hosts its own `packages/runner` loop, it is one more agent product. If it can wrap a third-party run as a session, it is the shared layer above all of them. The constraint is that Fold's semantics are only as good as what the harness lets us see and hold: an approval Fold cannot pause is not an approval, and a tool call Fold never sees cannot be replayed, claimed against or briefed.

The adapter question therefore reduces to four capabilities per harness: (1) can we observe every turn and tool step, (2) can we block a tool call until a quorum has voted, possibly hours later, (3) can we suspend and resume the run across runner death, and (4) can we fork at a checkpoint.

## Prior art

1. **Claude Agent SDK, permissions and hooks** (code.claude.com/docs/en/agent-sdk/permissions and /hooks, accessed 2026-10-02). Evaluation order is hooks, deny rules, ask rules, permission mode, allow rules, then `canUseTool`. A `PreToolUse` hook runs before every other step and its `deny` holds even in `bypassPermissions`; `canUseTool` is skipped for anything auto-approved earlier. `hookSpecificOutput.permissionDecision` is `allow`, `deny`, `ask` or `defer`; `defer` ends the turn with `stop_reason: "tool_deferred"` so the call can be resumed later. `updatedInput` rewrites arguments. `PostToolUse` can set `updatedToolOutput`; `SubagentStart`/`SubagentStop` carry `agent_id` and `agent_transcript_path`; `PreCompact`/`PostCompact` bracket compaction; `PermissionRequest` and `Notification` (`permission_prompt` after about six seconds waiting) exist. Hooks run in parallel; `deny` beats `defer` beats `ask` beats `allow`; default hook timeout is 600 s, after which the tool is not run and the model gets a tool result saying the hook did not answer.
2. **OpenAI Agents SDK, human in the loop** (github.com/openai/openai-agents-python, docs/human_in_the_loop.md, accessed 2026-10-02). `needs_approval` is a bool or an async callable over (context, parsed args, `tool_call_id`) that fails closed on malformed arguments. A run that hits one returns `result.interruptions` of `ToolApprovalItem` (`agent.name`, `tool_name`, `arguments`), including approvals raised inside handoffs and nested `Agent.as_tool()` runs, lifted to the outer run. `result.to_state()` yields a `RunState` with `approve(item, always_approve=)` and `reject(item, rejection_message=)`, serialisable by `to_json`/`from_json`; resume with `Runner.run(agent, state)`. Only `function_tool` and `as_tool` are interruptible this way; `ShellTool`/`ApplyPatchTool` use `on_approval` callbacks; `HostedMCPTool` uses `require_approval: "always"`.
3. **LangGraph interrupts** (docs.langchain.com/oss/python/langgraph/interrupts; egress-blocked, read via search snippets, UNVERIFIED in detail, accessed 2026-10-02). `interrupt(value)` pauses a node and surfaces the value under `__interrupt__` with an id; `Command(resume=value)` re-invokes with the same `thread_id`; a checkpointer is mandatory. On resume the node re-executes from its start, so side effects before the `interrupt` repeat. `get_state_history`, `update_state` and `checkpoint_id` give time travel and forking.
4. **Codex app-server protocol** (github.com/openai/codex, codex-rs/app-server/README.md, accessed 2026-10-02; the "JSON-RPC lite" framing is from a secondary blog, UNVERIFIED). Primitives are thread, turn, item. Methods: `thread/start`, `thread/resume`, `thread/fork` (branch at a turn), `thread/revert`, `thread/items/list`, `turn/start`, `turn/interrupt`; notifications `item/started`, `item/completed`, `item/agentMessage/delta`, `turn/completed`, `turn/aborted`. Item types include `agentMessage`, `reasoning`, `commandExecution`, `fileChange`, `mcpToolCall`, `webSearch`, `plan`, `todoList`. The server initiates `item/commandExecution/requestApproval` and `item/fileChange/requestApproval` and pauses the turn until the client answers `accepted`, `acceptedForSession`, `declined` or `cancel`. Compaction is automatic; `rollout/compress` is separate. A Guardian auto-review can trip a `tooManyDenials` circuit breaker.
5. **Fold kernel design** (docs/05_kernel_design.md, this repo). Approval ids derive from the content hash of the exact call; irreversible calls need an M-of-N quorum of distinct humans; a dead runner is replaced by one that finishes the open turn from state.

## Mapping to Fold events

| Fold event | Claude Agent SDK | OpenAI Agents | LangGraph | Codex app-server |
|---|---|---|---|---|
| Turn started / ended | `UserPromptSubmit`, `Stop`, result message | `Runner.run` boundary; `RunState` | graph invoke per `thread_id`; `__interrupt__` | `turn/start`, `turn/completed`, `turn/aborted` |
| Tool proposed | `PreToolUse` (`tool_name`, `tool_input`, tool use id) | `needs_approval` callable (`tool_call_id`) | only if the node calls `interrupt` | `item/started` for `commandExecution`, `fileChange`, `mcpToolCall` |
| Tool result | `PostToolUse`, `PostToolUseFailure` | run items after resume | node output / state update | `item/completed` |
| Approval requested | `permissionDecision: "defer"` or blocking hook | `ToolApprovalItem` in `interruptions` | `interrupt(value)` with id | `item/*/requestApproval` |
| Approval resolved | resume deferred call, or hook returns `allow`/`deny` with reason | `state.approve`/`state.reject` then `Runner.run(agent, state)` | `Command(resume={id: decision})` | response `accepted`/`declined` |
| Suspend / resume | `tool_deferred` plus session resume | `RunState.to_json` / `from_json` | checkpointer + `thread_id` | `thread/resume`; no portable snapshot |
| Fork at checkpoint | none native | none native | `checkpoint_id` | `thread/fork` |
| Nested agent | `SubagentStart`/`Stop` with `agent_id` | approvals lifted to outer run | subgraph interrupts bubble | not exposed as items (UNVERIFIED) |

## What to borrow

- **Defer, not block.** Claude's `defer` and OpenAI's serialisable `RunState` both end the turn cleanly with the pending call recorded, which is exactly the shape Fold's quorum needs: votes can take hours and the runner may die in between. Fold should model every approval wait as a suspension of the harness, never as a held-open callback.
- **Hash-bound approval after input rewrite.** Claude lets a hook change `updatedInput`; Codex approves a concrete command or patch. Fold's approval id must be computed over the post-rewrite call, and the adapter must re-request if the harness changes arguments after a vote.
- **Thread/turn/item as the wire vocabulary.** Codex's three primitives map one-to-one to Fold's session, turn and tool event; adopting the same names in the adapter interface keeps the Codex adapter thin and makes the other adapters legible.
- **Session-scoped grants as explicit events.** Codex's `acceptedForSession` and OpenAI's `always_approve` are standing permissions. Fold already has a constraints lattice; a standing approval is a constraint on the approval policy and should be an event the brief shows, not a side effect hidden in the harness.
- **Fail closed on malformed calls.** OpenAI's `needs_approval` fails closed; Claude treats a hook timeout as a non-run. Fold's adapter should do the same and record the refusal as a tool result the model can read, matching how fleet claims are refused today.

## What is unsolved

- **Steps Fold cannot see.** Claude: anything auto-approved by rules or mode bypasses `canUseTool` (hooks still fire, so the gate must be a hook), subagent transcripts arrive as a file path rather than events, and compaction rewrites context Fold did not author. OpenAI: hosted tools (web search, file search, code interpreter) run server-side with no interruption; handoffs appear as items but cannot be voted on. LangGraph: a `ToolNode` that never calls `interrupt` executes invisibly, and a resumed node repeats its pre-interrupt side effects, which would duplicate tool events in Fold's log. Codex: only `commandExecution` and `fileChange` carry approval requests; `mcpToolCall` and `webSearch` do not (UNVERIFIED), automatic compaction is invisible, and the Guardian can deny on its own authority.
- **Snapshot opacity.** OpenAI's `RunState` and LangGraph checkpoints are blobs. Fold can hash and store them, but a replica cannot fold them, so determinism holds only up to the blob boundary, and the docs warn against deserialising untrusted snapshots. Codex has no portable snapshot at all; a dead adapter loses the pending approval unless the app-server process survives.
- **Arbitrated intent has no inlet.** Every harness takes one prompt per turn. Fold's composed intent (goal, direction, constraints, frozen scopes) must be injected as a system fragment or prompt prefix; mid-turn directives can only reach the model between tool calls via hooks (`PostToolBatch` on Claude, nothing equivalent on Codex beyond `turn/interrupt`).
- **Quorum against single-decision APIs.** Each harness expects one yes/no. Fold's adapter must hold the harness request open or suspended while N humans vote, and must translate "any eligible deny denies" into a single rejection with a reason the model can read.
- **Workspace merge.** Codex `thread/fork` and LangGraph `checkpoint_id` fork the conversation, not the file tree. Fold's three-way workspace merge stays Fold's job and the adapter must snapshot the tree at the fork.

## Concrete recommendations for Fold

1. **Define a `HarnessAdapter` interface** in a new `packages/runner/src/harness.ts` with `startTurn`, `onToolProposed(call) -> Promise<"allow"|"deny"|"defer">`, `onToolResult`, `endTurn`, `suspend() -> OpaqueSnapshot`, `resume(snapshot)`, `fork(checkpoint)`. Extend `packages/protocol/src/index.ts` with a `harness` field on turn events, a `HarnessSuspended` event carrying the hashed opaque snapshot, and a `StandingApproval` event (tool pattern, risk class, granted-by, scope: session or turn).
2. **Rewrite the Claude adapter** (`packages/runner/src/claude.ts`) to gate on a `PreToolUse` hook, not `canUseTool`. Map risk class `read`/`write` to `allow`, `exec`/`external`/`irreversible` to `defer`; on `tool_deferred` emit Fold's approval-requested event bound to the post-`updatedInput` hash, and resume on quorum. Journal `PostToolUse`, `SubagentStart`/`SubagentStop` (as nested collapsed tool lines keyed by `agent_id`), and `PreCompact` (archive `agent_transcript_path`, emit a compaction event). Set an explicit hook `timeout` and treat a timeout as a deny with reason.
3. **Add an OpenAI Agents adapter** (`packages/runner/src/openai.ts`) whose `needs_approval` callable reads Fold's risk class from the tool registry in `packages/runner/src/tools.ts`. On `interruptions`, store `RunState.to_json()` in `HarnessSuspended` (encrypted at rest in `packages/server/src/storage.ts`), apply votes with `approve`/`reject`, resume with the original top-level agent. Render hosted tools as a quiet notice "ran outside Fold's control".
4. **Add a LangGraph adapter** (`packages/runner/src/langgraph.ts`) that requires a checkpointer, maps each `__interrupt__` id to an approval id, resumes with `Command(resume={id: decision})`, and makes tool results idempotent by `tool_call_id` in `packages/kernel/src/log.ts` so a re-executed node does not duplicate events.
5. **Add a Codex adapter** (`packages/runner/src/codex.ts`) speaking the app-server JSON-RPC over stdio: thread to session, turn to turn, item to message or tool event; answer `requestApproval` only after Fold's quorum, downgrading `acceptedForSession` to `accepted` unless a `StandingApproval` event exists; map `thread/fork` to Fold fork with a workspace snapshot; map Fold pause to `turn/interrupt`.
6. **Ship a fidelity badge and a conformance suite.** In `apps/web`, show per session which harness runs it and a one-line list of hidden step classes (hosted tools, auto-approved tools, compaction). In `packages/runner/test/harness-conformance.test.ts`, drive each adapter with the scripted model through allow, deny, quorum, suspend, resume and fork, asserting the same Fold event sequence from every harness.
